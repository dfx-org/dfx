# Contributing to dfx

Thank you for your interest in dfx!

## Please open an issue, not a pull request

We don't accept unsolicited pull requests. If you have found a bug, would like a feature, or have an idea, please [open an issue](https://github.com/dfx-org/dfx/issues/new/choose). A clear issue is the most helpful way to contribute: it lets the maintainers decide how a change fits the design of the library and implement it consistently.

## Reporting a bug

Please include:

- the dfx package and version you use, for example `dfx-cpu 1.0.10`
- your .NET SDK version, operating system, and whether you run on CPU or GPU
- a minimal code sample that reproduces the problem
- what you expected to happen, and what happened instead, including the full error message

## Requesting a feature

Describe what you would like to do and why. If you have an API in mind, sketch it; pointing to the equivalent in PyTorch or another library is often the quickest way to explain it.

## Questions

Questions are welcome as issues too.

## Security issues

Please don't report security vulnerabilities in public issues. See [SECURITY.md](SECURITY.md).
